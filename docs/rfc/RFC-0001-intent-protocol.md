# RFC-0001: OVG Intent Protocol

Status: Draft

Version: 1.0

Author: OpenVoiceGateway Project

Created: 2026-06-06

---

# 1. Abstract

This document defines the OpenVoiceGateway (OVG) Intent Protocol.

The Intent Protocol is the core communication format used between voice interfaces, gateways, AI agents, and tools.

Its purpose is to provide a unified structure for representing user intentions regardless of the source platform.

Examples of supported sources include:

- Siri
- Gemini
- Alexa
- Home Assistant
- AI Glasses
- AI Earbuds
- Future Voice Interfaces

The protocol is designed to be platform-independent, agent-independent, and extensible.

---

# 2. Goals

The OVG Intent Protocol aims to:

1. Standardize communication between voice systems and AI agents.
2. Provide a unified intent representation.
3. Support multi-platform voice integrations.
4. Support multi-agent execution environments.
5. Enable future protocol evolution without breaking compatibility.
6. Maintain simplicity for adapter and SDK developers.

---

# 3. Architecture Overview

Voice Interface
↓
OVG Adapter
↓
OVG Intent
↓
OVG Gateway
↓
Agent Runtime
↓
Tool Execution
↓
OVG Response

The Intent Protocol acts as the standardized payload exchanged within the OVG ecosystem.

# 4. Intent Structure

An OVG Intent MUST be represented as a JSON object.

Example:

json {   "version": "1.0",   "request_id": "3f8c7f4a-6e4e-4fcb-89f1-4f8c3d5b8e6c",    "source": {     "platform": "siri",     "device": "iphone"   },    "session": {     "session_id": "b7a2d9c8-0d7e-4f92-a8f1-f4e62fdb9e70"   },    "intent": {     "name": "record_idea",     "confidence": 0.95   },    "payload": {     "text": "Build an AI startup idea management system"   },    "metadata": {     "timestamp": "2026-06-06T12:00:00Z"   } } 

---

# 5. Required Fields

The following fields are REQUIRED.

## version

Protocol version.

Example:

json {   "version": "1.0" } 

---

## request_id

Unique request identifier.

Requirements:

- MUST be globally unique.
- UUID is recommended.

Purpose:

- Logging
- Auditing
- Tracing
- Debugging

---

## intent.name

Intent identifier.

Examples:

text record_idea create_ticket send_message book_meeting create_note 

---

## payload

Intent-specific data.

Payload schema is determined by the intent type.

---

# 6. Optional Fields

## source

Information about the origin platform.

Example:

json {   "platform": "siri",   "device": "iphone" } 

Examples of platforms:

text siri gemini alexa home_assistant carplay android_auto custom 

---

## session

Conversation context information.

Example:

json {   "session_id": "..." } 

Purpose:

- Multi-turn conversations
- Memory systems
- Agent continuity

---

## intent.confidence

Confidence score generated by the originating platform.

Range:

text 0.0 - 1.0 

Example:

json {   "confidence": 0.93 } 

---

## metadata

Additional contextual information.

Example:

json {   "timestamp": "2026-06-06T12:00:00Z",   "locale": "en-US",   "timezone": "Asia/Tokyo" } 

---

# 7. Intent Naming Convention

Intent names MUST use:

text verb_noun 

format.

Examples:

text record_idea create_ticket send_message create_note book_meeting search_document 

The following styles SHOULD NOT be used:

text RecordIdea recordIdea Record_Idea 

Reason:

- Human readability
- Cross-language compatibility
- SDK consistency

---

# 8. Payload Rules

Payload contents are intent-specific.

Example:

Record Idea

json {   "text": "Build a voice-first AI operating system" } 

Create Ticket

json {   "title": "Fix payment issue",   "priority": "high" } 

Send Email

json {   "to": "user@example.com",   "subject": "Meeting Notes" } 

OVG Core MUST NOT enforce payload schemas globally.

Payload validation SHOULD be delegated to intent handlers.

---

# 9. Forward Compatibility

Future protocol versions MAY introduce:

- Agent routing
- Tool preferences
- Permission scopes
- User profiles
- Memory references
- Workflow definitions

Implementations MUST ignore unknown fields.

This ensures compatibility between protocol versions.

---

# 10. Design Principles

The OVG Intent Protocol follows these principles:

1. Platform Agnostic
2. Agent Agnostic
3. Tool Agnostic
4. Extensible
5. Backward Compatible
6. Human Readable
